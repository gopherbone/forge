Forge Pipeline Retrospective

The day's work covered eight projects in 16 hours. Forge reliably proves that a part will print. It doesn't help an agent work out whether a mechanism makes sense before it writes CAD. The projects that did the maths first went straight through, and the two that didn't took longest. The fix is a cheap sketch stage between the spec and design.py, built from tools that already half-exist.

What forge does really well

Stale results are refused

stages._current raises when design.py, spec.yaml or forge/data changed since the build. forge status shows it today: snapbox and jumping-frog read "design/spec changed since build" on every stage after build. verified

So their numbers on this page come from the journal, labelled as such. The rule cost time too, as Wheel-spinning #8 shows.

FEA that was made to fail first

tests/test_fea_validation.py asserts Timoshenko deflection within 4%. The README reports 1.3%. Displacement control matches force control within 8% and beam theory within 15%. The coupling exists because snapbox v1 was 2.8× too stiff, and an agent diagnosed that instead of shipping it. verified test suite

The sim engineer's trust checklist caught three boundary-condition artefacts: the automaton shoulder clamp at 07:21, the deck clamp at 08:34, and the clip's symmetry slab.

Real slicing, checked

Presets are flattened, and presets_applied compares the G-code header with the request. The hard-won fact: a raw preset slices with a 200×200 bed, PLA and 0 g. Every time and gram figure on this page is a Bambu estimate from that path. verified

Every check can fail

18 tests in test_checks_fail.py, including bed-edge rounds, domes, supports without opt-in, thin Z gaps and undeclared touching parts. New user rules became checks within the hour (up_curves 03:23, retention 03:47, sharp_corners 02:56). verified

Physical feedback becomes rules

The snapbox print (0.4 mm engagement, about 0.9 N) gave no felt click. That became the ≥ 1 mm, 5-15 N rule, and every later snap was sized to it: rack-frame latch t 1.6 → 1.8 because 4.55 N was under 5 N. Curled 45° chamfers became bed_edge. The gator clip "worked excellently". The user printed an earlier revision with no build recorded, so it isn't evidence for 9e3f6e77. verified journal

One human gate, and a journal worth mining

Dropping to a single print gate (user, 05:15) didn't lose control. Approvals bind to a build hash, and three releases went out at 13:43. Each journal is a timestamped decision log, detailed enough to reconstruct this retrospective without asking anyone. verified

Studio puts the human in the loop early

The user spotted "spacing issues" on a studio screenshot of rack-frame v2 (03:46), and forge gained the undeclared-touching warning. That's the cheapest review in the system. The sketch stage below gives it something to show before any CAD exists. verified journal

Where we're spinning our wheels

1 · Mechanisms designed in CAD

rack-frame: 3 h 20 m discarded

The motion sweep checks the kinematics that design.py asserts. Parts are placed from crank_deg by the designer's own formula. The sweep can prove that nothing collides. It can't prove that the asserted motion is what the contacts would produce. Rack-frame v2 passed a 72-pose sweep with 0 collisions and was still rejected.

v2 even had a shapely solve (03:28), but no DOF table, no free-body diagram and no swept-width budget. mechanism.md §4b shows that the spec was infeasible by arithmetic: 2 teeth each way needs about 140 mm against a 120 mm limit. verified journal + mechanism.md

2 · Stress concentrations chased with FEA

automaton R7: ~11 h open

Crank SF went 1.75 → 1.52 (singularity, +32% on refinement) → 1.65 → 1.12 → 1.43 → 1.18 (unconverged, 17.5%). A hand calculation existed, at 06:57 and 07:21: nominal von Mises about 11 MPa, SF about 4. The real problem was Kt ≈ 2.6 at a shoulder the plate rule wouldn't let the designer fillet. Rack-frame (1.88 → 2.24) and 114 (1.81, then 1.94) hit the same shaft-to-hub shoulder. estimated FEA

Corrections to the brief

Several of the lead's observations change shape when checked against the files. The proposals below are built on the corrected versions.

  • Automaton shaft: it wasn't found "only at full FEA, late". Fast FEA flagged SF 1.75 at 03:45, and a nominal hand calculation passed it at SF about 4. A shaft screen pays off only if it includes Kt and the plate-rule conflict. A nominal-only screen would have passed this shaft.
  • Rack-frame: v2 already had a 2D contact solve. What solved v3 was the bundle: DOF table, free-body diagram, swept-width budget and a tolerance sweep of the contact study. So the gate has to require all of these, not just a solver run.
  • study_2d.py metrics are wrong: its ok flag is false on all 24 rows, including the chosen R7/p6, because 0.04 mm tail steps fail min_step > 0.5. mean_step reads 3.14 for a 6 mm step, and per_rev_mm spans two revolutions (47.98 means 24 mm/rev). The decision was right because it was read off the figure. The productised tool must fix these.
  • "p ≤ 5 runs away": the saved study shows p = 5 jams at d = 2.0 (17 unresolved steps, R 6-8) and runs away only at R 8 / d 1.6 (40 mm/rev). p = 6 gives 24.0 mm/rev at every depth and radius. measured 2D
  • FEA validation: the test asserts 4%. The 1.3% is the README's measured claim.
Centrepiece

Sketch before CAD

Before an agent writes design.py, it should hold a solved 2D mechanism and closed-form margins for every shaft, snap and flexure, plus an envelope that fits. All of it should run in seconds and write a hash-stamped result like every other forge stage.

#4 · the centrepiece tool

forge sketch: 2D kinematic and contact studies

effort M-Lpayoff highest for mechanismsmeasured

Generalise study_2d.py into a library and a stage. A project gets an optional sketch.py that returns a forge.sketch.Study: shapely profiles from a primitive library, joints, a driver, and tolerance parameters to vary. The solver steps the driver. Each follower is either pushed along its free DOF until clear (push-only, as in the prototype, using bisection instead of 0.02 mm increments), or placed by closed-form loop closure (linkages), or allowed to fall back under gravity (cam followers). design.py then imports the same profiles and extrudes them, so the mechanism that was solved is the one that gets built. v3 already did this by hand: "Drive re-solved with study_2d.cam_shape".

CLI shape 
forge sketch rack-frame                   # all studies, nominal + extremes
forge sketch rack-frame --study drive \
     --vary depth=0.9,1.6,2.0 --reverse
forge sketch new geneva --slots 4 --pin-r 2
forge sketch rack-frame --svg             # build/sketch/drive.svg (animated)
Primitives (first cut)
  • blade_cam, sawtooth_rack (from study_2d)
  • involute_sector, straight_rack (mutilated pinion; bd_warehouse profile)
  • ratchet + pawl (pawl as a PRBM spring)
  • geneva, pin_slot, four_bar, slider_crank
  • cam_follower (flat, knife, roller; gravity return)
Outputs → build/results/sketch.json
  • Travel per rev, and advance per driver pass binned by blade or tooth index. The prototype's run-length metric must go.
  • Dwell fraction; jams (overlap not resolvable along the free DOF = wedge); runaway (advance > 1.3 × pitch).
  • Minimum clearance per pair over the cycle, neutral gap, and re-entry capture range.
  • Contact normal angle → with μ = 0.3, the force ratio pushed into each constraint (e.g. vertical load on A's detent). estimated
  • The swept 2D envelope, fed to forge budget.
  • An animated SVG for studio's Assembly mode and a front-elevation silhouette for the critic.
Acceptance tests (from the day's incidents)
  1. Rack-frame drive R 7, p 6, tb 2.0: 24.0 ± 0.1 mm/rev and 4 advances of 6.0 ± 0.1 mm per rev, 0 jams, at d = 0.9, 1.6 and 2.0.
  2. Known-bad: R 7, p 5, d 2.0 must report a jam. R 8, p 5, d 1.6 must report runaway (40 mm/rev).
  3. Neutral gap R 7, p 6, c 1.0 = 1.00 ± 0.01 mm (prototype: 1.002).
  4. Reverse crank on the v3 drive: no mid-travel jam, and a stall at the hand stop (journal 07:18).
  5. 114: z 15, N 5 stub teeth give contact ratio 1.28 and ≥ 3.28 mm to the idle rack. Known-bad: z 12-14 with 4-5 full-depth teeth engages both racks (lock).
  6. Analytic: a 4-slot Geneva dwells 270°. A four-bar matches closed-form loop closure within 0.01 mm. Grashof classification is correct.
  7. Each study runs in under 5 s, and the result goes stale when sketch.py or spec.yaml changes.
#1

Concept card and the sketch precondition

effort Sheuristic

This turns mechanism.md into a template and a check. The card has five required blocks: a DOF table (part, free, held by), a free-body diagram as a force list with magnitudes, a budget, the studies, and the screens. It ends with rule conflicts: places where a needed feature fights a user rule. The automaton shoulder fillet against bed_edge is the example that would have surfaced at concept. The ~140 mm width against 120 is another, and the user resolved it in one message once the number existed.

CLI shape 
forge concept rack-frame --init   # writes concept.md from spec R-numbers
forge concept rack-frame          # validates → results/concept.json
Skill change
  • Phase 1 ends with a current concept.json. The lead doesn't dispatch forge-designer for design.py without it, and forge build lists a missing card as a FAIL row (not a gate, never in approvals.json).
  • For reference reproductions (rack-frame, 114), the engraving checklist moves onto the card.
Acceptance tests
  1. Rack-frame v2's state (solve present, no DOF or width) fails the card with "budget missing".
  2. A card whose budget exceeds the spec R1 envelope fails and names the overrun.
  3. A card with an unresolved rule conflict passes only when the conflict is listed with a decision.
  4. Editing sketch.py makes concept.json stale.
  5. Designs with no Motion and no flex LoadCase (snapbox-type boxes) don't need a card.
#2

forge screen shaft: sections with Kt, before CAD

effort Sestimated

Bending plus torsion on a named section (round, D-flat, triple-flat, rounded square), with Peterson-style Kt for the shoulder fillet, SF in XY and Z from the print orientation, and the minimum fillet for the target SF. If that fillet lands in the bottom 2 mm at the plate, the screen reports the conflict and lists the escapes the journals found: lofted flare, larger section, purchased D-rod, or moving the shoulder off the bed plane. Automaton spent the day on this exact question.

CLI shape 
forge screen shaft --section rsquare:4.6,r0.8 \
   --M 130 --T 95 --shoulder D=12,r=0.35 \
   --orient lying --sf 2
forge screen shaft automaton --from-loadcase crank_push
Acceptance tests
  1. Automaton 4.6 mm square, M 130, T 95: nominal VM 11 ± 1.5 MPa and SF about 4 (journal hand calc 06:57, converged stub 8.5-8.9 MPa at 07:21).
  2. Same section with a sharp shoulder (r → 0): FAIL, "Kt unbounded, fillet required".
  3. r 0.35 (r/d 0.076): Kt_b about 2.0, SF 2.2-2.4 (journal estimate 07:21).
  4. A fillet in the bed zone is reported as a bed_edge conflict.
  5. A pin printed upright (the gator's Ø3 × 9 warning) uses the Z strength.
#3

forge budget: swept envelope and Z stack

effort Smeasured from sketch · heuristic from formulas

The spec gets a budget: block: width terms like 2F + 6T + 2(gap + bearing) from mechanism.md §4b, and a Z stack (desk clearance, shaft, cams, deck). Every Z value is snapped to the 0.2 mm grid. With a sketch present, the 2D swept extents replace the formula terms. The point is to put the 140 mm number in front of the user at concept time instead of at v2.

CLI shape 
forge budget rack-frame          # width/height/depth vs R1
forge budget automaton --what-if shaft_d=6.5
Acceptance tests
  1. Rack-frame T 12: 138-146 mm (later measured sweep: 143.8 / 144.0). T 6: 100-110 mm.
  2. An off-grid Z (e.g. 0.3) is flagged with its nearest layer multiple.
  3. Automaton --what-if shaft_d=6.5 reports the stack growth the 10:56 note feared ("cams and stack grow").
#5

forge screen snap: the felt rule in one command

effort Sestimated

Extend forge flex cantilever. Today it knows no engagement, no clearance, no across-layer factor (strain_allow_z_factor lives only in fea.py) and no root concentration. Add lip, gap, catch angle, root radius and bend plane. Report engagement, the push window, strain against the in-layer or across-layer allowance, and a root Kt. Calibrate Kt against the journal's closed-form vs FEA pairs and store them as fixtures.

CLI shape 
forge screen snap --L 16 --t 1.6 --b 14 \
   --lip 1.2 --gap 0.2 --angle 45 --root-r 2 \
   --plane in --use repeated
Acceptance tests
  1. Snapbox v2 (lip 0.6, gap 0.2): engagement 0.4 → "not felt" FAIL, whatever the force.
  2. Rack-frame pedestal latch: flags t 1.6 as marginal against the 5 N floor (FEA gave 4.55 N), and t 1.8 passes (journal 07:18).
  3. Across-layer bending uses 0.6 × the allowance.
  4. Calibration: the rack-frame detent (FEA about 1.7× beam theory at the root, journal 04:52) and snapbox v1 (beam 0.84%, BC-corrected FEA 1.49%) both fall inside the screen's stated band once root Kt is applied. If they don't, the band is widened and recorded.
#7

forge prbm: compliant mechanisms as springs and pivots

effort Mestimated

Use the pseudo-rigid-body model (Howell): a short flexure is a pin with a torsion spring K = γ KΘ EI / L (γ ≈ 0.85, KΘ ≈ 2.65), and a long one is a 1R or 2R chain. This gives a force-deflection curve, stored energy and stop angle in milliseconds, plus a strain estimate with curved-beam correction for U-turns. It fills the gap between forge flex (small deflection) and nonlinear FEA (minutes per run, timeouts). The gator designer already hand-computed the hinge stiffness (184 N·mm/rad), then ran six FEA loops to find the force and opening. When an FEA curve exists, the plot overlays it so the gap is visible.

CLI shape 
forge prbm gator-clip --topology clothespin \
   --hinge L=26,t=1.9,b=9 --arm 30 --theta 0.38
forge prbm jumping-frog --topology c-spring \
   --strip t=2.0,R=4 --press 6.35 --curve
Acceptance tests
  1. Jumping frog C-spring: within ±25% of the full-run FEA, 4.87 N at 6.35 mm, 16.2 mJ (journal 04:07).
  2. Gator v4 geometry: open force within ±25% of 6.16 N at 0.380 rad (journal 05:50).
  3. Small-angle limit equals forge flex hinge within 5%.
  4. The output is labelled estimated, with "confirm with a nonlinear LoadCase".

Other fixes that stop late discoveries

#6

FEA job lock, preflight and local convergence

effort S
  • Use a machine-wide ccx semaphore (one solve per 8 threads, queued with a visible wait), so parallel projects don't push each other past the 1800 s limit.
  • Make the gator's ad-hoc preflight standard: a linear solve at 0.65× mesh first, which fails fast on inverted tets before the nonlinear pass.
  • Refine only inside refine regions during convergence (rack-frame 08:42 found the whole cam meshed fine, a 54 MB deck), with a node budget that rejects a run above about 300k nodes instead of letting it die at 483k.
  • Snapshot forge/data into the build at run start, so a mid-run rules edit by another session doesn't make the run stale.

Acceptance: two concurrent forge run calls finish without timeouts. A sliver fixture fails in preflight in under 60 s. Editing rules.yaml during a run doesn't stop it, and the next build picks the change up.

#8

forge seam: put the scratch scripts in the toolkit

effort Mmeasured

Parse outer-wall start points per layer from the plate G-code, map them back to each part's frame through the 3MF item transform (the arranger rotated the gator 53° and normalised A's rotation), and report seams within 1 mm of snap roots, FEA peak nodes and declared contact faces. A pre-slice prediction is harder and less trustworthy. Verify after slicing, which is cheap and exact.

Acceptance: it reproduces 114's HANDBACK.md table (post seams 39/39 on the V-notch). Known-bad: the pre-fix rack-frame crank shows 23/23 layers on the snap root, and the gator under back shows 43 mouth seams.

#9

Deflected-flexure clearance

effort Mestimated

The sim npz already holds nodes and U. Deform the surface mesh at peak deflection and run the fit stage's distance check against the rest of the part and its partner. That covers the automaton frog finger, whose cavity was found by hand (1.0 → 1.7), and the rack-frame drag leaf that "ran into A's crown".

Acceptance: the automaton frog_1 finger with a 1.0 mm cavity reports contact (0.1-0.36 mm short), and the 1.7 mm cavity passes.
